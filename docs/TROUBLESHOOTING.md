# 踩坑记录与解决方案

> 按“现象 → 根因 → 排查 → 解决 → 验证 → 复发风险”记录。每条尽量给出相关文件，便于后续 AI/开发者直接定位。
> 验证标记沿用 README 的约定：✅ 已验证 / ◐ 合理推断 / ○ 未验证 / ✗ 未解决。

## A. 注入与 frame 类

### A1. 学习通章节页（studentstudy）点开始没反应

- **现象**：Wayground 正常，学习通章节页/随堂测验页按钮无反应，日志无“已启动”。
- **根因**：`sites.js` 最初只匹配路径含 `/exam` 或 `/work`；`studentstudy` 这类章节学习页不在其中，`siteForUrl()` 返回 null。
- **排查**：看 `background.startRun` 是否走到“当前标签页不是支持的…”。
- **解决**：学习通匹配改为**任意 `*.chaoxing.com`**；只读页（`/work/view`、`/exam/analysis`）单独拦截。
- **验证**：✅ 后续真机可启动。
- **复发风险**：低。新增站点时容易再次按路径过窄匹配。

### A2. 题目在 iframe 里，只扫顶层永远 0 题

- **现象**：探测 0 题，但页面明明有题；DevTools 里题目在 `#iframe` 内。
- **根因**：早期只向顶层 frame 注入/探测；学习通章节页真正内容在 `knowledge/cards` / `module/work` 等子 frame。
- **排查**：探测诊断的 iframe 列表；`location.href` 与页面 URL 不一致。
- **解决**：`pickFrame` 全 frame 注入 + 逐 frame `WG_PROBE`，按题数择优；0.5.2 起用 `webNavigation` 获取真实 frame 列表。
- **验证**：✅ 真机 0.5.2 识别到 11 题。
- **复发风险**：中。跨域/`about:blank`/动态创建的 frame 仍可能漏；靠 `match_about_blank` + 全帧权限兜底。

### A3. 探测/开始“卡住”，点按钮没反应，刷新页面才恢复

- **现象**：点探测长时间无响应，Ctrl+F5 后才出现日志。
- **根因**：早期每次探测都全帧递归扫描 + 大量 `innerText`/`getBoundingClientRect` 计算；页面节点多时阻塞消息通道。
- **排查**：Service Worker 日志停顿；页面 CPU 占用；探测耗时。
- **解决**：改为逐 frame 探测、结果缓存、只在必要时注入；移除高成本的 `fallbackByLabels`（它对每个 div 调 `cxPlain.count`）。
- **验证**：◐ 用户反馈“刷新后正常”；未做性能量化。
- **复发风险**：中。`labelBlocks()` 与 `controlBlocks()` 仍会遍历全文档，超大页面仍可能卡。

### A4. `No frame with id 193 in tab with tabId ...`

- **现象**：启动/停止时报错，运行中断。
- **根因**：页面刷新或跳转后旧 `frameId` 失效，background 仍向旧 frame 发消息。
- **排查**：错误文本即答案；看 `tabs.onUpdated` 是否复位。
- **解决**：停止改为广播 `WG_STOP`（不带 frameId）；`tabs.onUpdated/onRemoved` 清 frame 缓存并复位运行态；启动前先停旧运行；启动失败复位。
- **验证**：✅ 报错消失，用户可连续操作。
- **复发风险**：低。但 SPA 页面内 URL 不变、frame 重建时仍可能命中旧缓存；`pickFrame` 每次都会重新探测缓存 frame，探测失败会清缓存。

### A5. 真机探测显示“未获取到页面信息 / 识别到 0 个选项，策略 none”

- **现象**：不是“识别到 0 道题”，而是**没有快照**；状态卡片写“未获取到页面信息”。
- **根因**：内容脚本在该页所有 frame 都没有响应。可能是动态注入失败、扩展上下文失效（旧脚本残留）、frame 不可注入，或面板/扩展版本不一致。
- **排查**：0.5.2 起日志会输出 `脚本注入：…` 与逐 frame `自检 #N v版本 adapter=有/无 main=有/无 URL`；若显示 `自检失败：Cannot access contents...` 则是站点权限/注入限制。
- **解决**：
  1. 学习通改为**静态内容脚本**（`all_frames` + `match_about_blank`），页面加载时脚本已就位，不再依赖点击时注入；
  2. 用 `webNavigation.getAllFrames` 枚举真实 frame；
  3. 0 题时自动补注入 + 400ms 后重试探测；
  4. 探测失败时把自检结果直接写进面板日志。
- **验证**：✅ 0.5.2 真机解决（识别 11 题）。
- **复发风险**：中。扩展重新加载后，**已打开页面里的旧内容脚本会失效**，必须刷新页面；面板页脚已提示“刷新页面后需重新开始”。

### A6. Wayground 快照没有 `count` 字段，通用 frame 择优把它当 0 题

- **现象**：0.5.2 改动后 Wayground 可能“未识别到题目”。
- **根因**：`frame.js` 早期只用 `snapshot.count > 0` 判断可用；Wayground snapshot 只有 `options`。
- **解决**：0.5.3 引入 `usable()`（`count > 0` 或 `options.length > 0`）与 `weight()`（题数 ×1000 + 选项数）。
- **验证**：○ 代码修复，**未真机复测 Wayground**。
- **复发风险**：中。新增站点若快照结构不同，需要同步更新 `usable/weight`。

## B. 识别与解析类

### B1. 只有“纯选择题”的章节能识别，混合“选择题 + 简答题”的章节 0 题

- **现象**：同一门课，A 章探测 5 题正常；B 章探测 0 题，自动答题也无动作。
- **根因（多因叠加）**：
  1. `findContainers()` 命中第一个有结果的选择器就 `return`，其它选择器下的题目永远不扫；混合卷里选择/简答可能用不同容器类；
  2. `hasAnswerable()` 要求存在输入控件/选项块，简答题若编辑器尚未渲染会被整块过滤；
  3. 外层“整卷包装”元素匹配选择器后被当成**一道题**；
  4. 扫描异常会中断整次探测。
- **排查**：探测诊断里的“容器命中”（各选择器 raw/visible/labelled）、`typeName`、候选标签、题数与题型分布。
- **解决（0.5.0/0.5.1）**：
  - 合并所有容器选择器，不再提前返回；
  - `[typeName]` / `data-type` 直接映射题型；
  - 增加“题型标签锚定”兜底；
  - 外层包装若包含多个内层题目块则拆分；
  - 每题 `try/catch`，单题失败不影响其它题。
- **验证**：✅ mock 10/10（`single×4 / short×5 / multiple×1`）；✅ 真机 0.5.2 识别 11 题。
- **复发风险**：中低。题型标签被字体加密且无 `typeName` 的极端页面仍可能只识别到控件型题目。

### B2. 整卷包装层被当成一道题，明明有 10 题只识别 1 题

- **根因**：容器选择器同时匹配外层列表与内层题目；`outermost()` 只保留外层。
- **解决**：`pickQuestionNodes()` 检测“单块内含多个题型标签/多个命中内层块”，用内层块替换外层；合并阶段也会丢弃“包含 >1 个其他候选块”的超大块。
- **验证**：✅ mock Case C（外层 `.TiMu` 包两道内层题）正确拆为 2 题。
- **复发风险**：低。

### B3. 两个来源命中同一题目块，去重把两份都删掉（漏题/0 题）

- **现象**：标签锚定与控件反推都找到了同一题，但最终题数反而少 1。
- **根因**：`extra.filter(el => !arr.some(other => other.contains(el)))` 没有排除“自身”；相同元素 `contains` 自身为 true，两份互相判重全部被删。
- **解决**：条件改为 `other !== el && other.contains(el)`；后续合并再用全等判断跳过重复。
- **验证**：✅ mock 复现并修复（Case D 恢复）。
- **复发风险**：低，但属于“容易写错的去重模式”，其它合并逻辑应复用同一工具函数。

### B4. 简答题容器没有已渲染的编辑器 → 整题被过滤

- **现象**：选择题都识别，简答题不见。
- **根因**：`hasAnswerable()` 仅看输入控件；简答题编辑器可能懒加载或在 `iframe` 内。
- **解决**：允许“题型标签为简答/论述/名词解释”的容器在暂无编辑器时也算有效；`hasAnswerable` 纳入任意 `iframe`、`.Answer`、`.ui-input-text`。
- **验证**：✅ mock Case B（`typeName=简答题` 且无编辑器）被计入。
- **复发风险**：低。真正运行到该题时若仍无编辑器，会标记“无可用输入控件”失败。

### B5. 题干数字被误删：`5G` 变成 `G`

- **根因**：`cleanStem` 用了 `^[\s\d.、,，]+` 直接裁剪开头所有数字/标点，把“5G”中的 5 当题号删掉。
- **解决**：只裁剪“题号格式”——`第 N 题` 或 `数字 + .、,，)）`；先删题型括号再裁题号。
- **验证**：✅ mock 中 `5G`、`OSI` 题干完整保留。
- **复发风险**：低。

### B6. 学习通题干/选项出现“庝 / 庡 / 庤”等乱码

- **现象**：探测快照里的题干是随机汉字，模型答案质量下降。
- **根因**：学习通字体反爬（自定义字体把随机码位映射为正确字形），`innerText` 取到的是替换字符。
- **排查**：对比页面显示文字与 `innerText`；检查页面是否加载自定义 `@font-face`。
- **解决**：✗ **未解决**。当前只是把乱码原样发给模型。
- **可能方案**：按题截图 + 视觉模型 OCR；解析字体 cmap 建立映射表；读取页面渲染后的字形。
- **验证**：无。
- **复发风险**：高，且是**准确率层面的头号未解决问题**。

## C. 作答与写入类

### C1. 选项实际点上了，插件却标“失败”

- **根因**：无 `input` 的选项块点击后不会出现 `checked`；插件早期硬校验选中 class，页面 class 与预期不一致。
- **解决**：`cx-fill.choose` 对无 `input` 的选项只做点击，不再硬校验；仅在多选时校验“没有选到非目标项”。
- **验证**：✅ 用户真机反馈“其实成功”。
- **复发风险**：低。代价是极端情况下可能把“没点上”当成成功（需看页面表现）。

### C2. 填空题/简答题有编辑区却完全不填

- **根因**：早期只识别 `input`；`textarea`、`contenteditable`、UEditor 未纳入；且 0.4.x 的 `collectEditor` 未回退到任意 iframe。
- **解决**：
  - `collectInputs` 支持 `input/textarea/contenteditable`；
  - `collectEditor` 支持 `textarea[name^=answerEditor]`、`iframe[id*=ueditor]`、任意 iframe 回退；
  - `fillBlanks` 无 input 时回退到编辑器；
  - 考试模式下每题写完点“保存”。
- **验证**：✅ 真机客观题 10/10 填写（0.5.2）。
- **复发风险**：中。不同版本学习通的编辑器结构仍有差异。

### C3. 简答题 UEditor 看着有字，但保存后是空的

- **根因**：UEditor 的真实内容在其内部 iframe / UE 实例中；只写隐藏 textarea 不会同步；只写 iframe body 也可能不触发内部 model 更新。
- **解决（多路兜底）**：
  1. 写隐藏 `textarea` + `blur`；
  2. `UE.instants` 中找“容器属于当前题目”的实例，`setContent()`；
  3. `UE.getEditor(id)`（id 来自 textarea 或 `ueditor_0` 去前缀）；
  4. 写 `iframe.contentDocument.body.innerHTML` 并派发 `input/change`；
  5. 若找到实例，再同步一次 textarea。
- **验证**：○ 0.5.3 已实现，真机未复测；0.5.2 在写入前就抛异常，未走到这里。
- **复发风险**：中高。不同 UEditor 版本/多编辑器同页时，实例定位可能不准。

### C4. 最后一题简答报 `Illegal invocation`，整卷停在 10/11

- **现象**：日志 `停止：运行异常：Illegal invocation`，最后一题未做。
- **根因**：题目 DOM 属于子 frame，但操作发生在父 frame（父 frame 通过 `roots()` 递归看到了子 frame 的题）。`setNativeValue` 用 `instanceof HTMLTextAreaElement` 判断类型，跨 realm 时判断失败，走了 `HTMLInputElement.prototype` 的 value setter；用 input 的 setter 去写 textarea → **Illegal invocation**。异常未被局部捕获，`run()` 整体停止。
- **排查**：看停止日志出现在第 N 题之后；该题类型为 short；链路只在该题首次调用 `setNativeValue`（textarea）。
- **解决（0.5.3）**：
  - `cx-adapter.scan` 只接受 `ownerDocument === document` 的题目，父 frame 不再代管子 frame；
  - `frame.pickFrame` 题数相同时优先更深 frame；
  - `setNativeValue` 按 `tagName` + `el.ownerDocument.defaultView` 取原生 setter；
  - `cx-main` 对 `handle()` 整体 `try/catch`，单题失败只标该题。
- **验证**：✅ mock 扫描回归通过；✗ 真机未复测。
- **复发风险**：中。`getComputedStyle` 等其它原生调用仍可能跨 realm，但当前只发现 setter 这一处。

### C5. “跳过已作答”没效果，已答题被重做

- **根因**：`isAnswered()` 早期只要“任一选项带某个 class”就算已答，或全局 `doneKeys` 误判；页面 class 与实际选中态不一致。
- **解决**：
  - 单选/判断要求**恰好 1 个**选中；多选要求 **>0 且 < 全部**；
  - 识别 `check_answer_bg`、`check_answer`、`cur/selected/checked/active` 以及 `aria/data` 属性；
  - 题目 key = 类型 + 题干 + 选项文本，命中 `doneKeys` 也跳过；
  - `doneKeys` 按页面 URL 隔离。
- **验证**：◐ 用户反馈“不再重复”；未做逐题统计。
- **复发风险**：中。题干乱码（字体加密）会改变 key，导致同一题换页后判为新题。

### C6. 不同章节/考试互相“跳过”，第 8 题莫名被跳过

- **根因**：`DONE_KEY` 曾是全局键，所有页面共享已处理集合。
- **解决**：`DONE_KEY = wg_exam_done_v1:${origin}${pathname}${search}`；清空缓存时一并删除所有 `wg_exam_done_v1*`。
- **验证**：✅ 用户真机反馈问题消失。
- **复发风险**：低。若页面 URL 含一次性 token，key 会变化导致跳过失效（见 KNOWN_ISSUES）。

### C7. 低置信度题目不填，被标“跳过”

- **根因**：早期有“低置信度暂停/跳过”策略，与用户诉求冲突。
- **解决**：删除面板开关与配置项；低置信度仍填写，徽标显示如“模型作答 35%”。
- **验证**：✅ 按用户要求调整，真机不再因置信度跳过。
- **复发风险**：低；但 `main.js`（Wayground）仍残留 `pauseOnLowConfidence` 死代码。

### C8. 切回 DeepSeek Flash 后明显变慢

- **根因**：曾对每题做“二次复核/高准确率复核”，等于每题两次模型调用。
- **解决**：删除复核，单选/多选/填空每题一次调用；简答 `temperature 0.2`，其它 0。
- **验证**：✅ 用户反馈速度恢复。
- **复发风险**：低。

### C9. 一题多个空：答案全部塞进第 1 空，或只填第一个

- **现象**：题干有 2–3 个 `____`，页面有对应数量的输入框，但只有第 1 个框被填写，且内容可能是几个答案拼在一起；后续再跑又被判“已作答”。
- **根因（三层）**：
  1. 模型有时把多个空的答案合并成一个字符串放进 `blanks[0]`（如 `"甲；乙；丙"`），旧 `fillBlanks` 只按数组下标写入；
  2. `isAnswered()` 对填空题用 `some()`，任意一个框有值就算已答；
  3. **缓存污染 + 旧 DOM 引用**：旧版本把错题答案写入缓存，且填写时使用扫描阶段已失效的输入框引用，导致日志显示“已填/缓存命中”但页面输入框仍为空。
- **排查**：日志是否全部“缓存命中”；探测快照的 `空格数`；页面输入框是否在点击后被重建。
- **解决（0.5.4 / 0.5.5）**：
  - 0.5.4：合并答案拆分、逐框校验、`every()` 判断全部空格；
  - 0.5.5：**禁用填空缓存**；缓存条目校验题面/题型/空格数；`fillBlanks` 写入前后重新查询输入框，延迟校验并补写。
- **验证**：✅ 3 空 mock（模拟输入框被重建）：`甲/乙/丙` 分别写入三个框，`complete=true`；清除后两空后 `answered=false`。
- **复发风险**：低。若模型只给一个不含分隔符的答案，仍只会填第 1 空并标记“部分空未填”。

### C10. 刷新后 0/12 全部“跳过”，但输入框是空的

- **现象**：整卷日志“0/12 已填，跳过 12 题”，所有题带“跳过”徽标，页面实际空白。
- **根因**：
  1. 跳过条件曾使用容器 class 正则（`done|answered|complete|finished|saved`），页面普通 class 可能误命中；
  2. 历史 `doneKeys` 持久化在 `chrome.storage.local`，页面刷新丢失草稿后仍把题目判为“已处理过”。
- **解决（0.5.4）**：跳过只依据当前 DOM 的 `q.answered`；移除 class 正则与 `doneKeys` 兜底跳过。
- **验证**：◐ 代码层修复；需真机复测该作业页。
- **复发风险**：低。若已答检测本身失败，可能重复作答（可接受，不会漏答）。

### C11. 一页多个任务点，只识别/作答第一个

- **现象**：页面有“作业”和“章节测验”两个任务点，探测 12 题、全部答完，但第二个任务点的题目完全未处理。
- **根因**：学习通启动时 `pickFrame` 只选“题数最多的一个 frame”，第二个任务点位于另一个 frame，永远不会收到 `WG_START`。
- **排查**：启动日志的“任务点分布”；探测快照的 `各 frame` 是否显示两个有题 frame。
- **解决（0.5.5）**：新增 `pickFrames`，学习通同时启动所有有题目的 frame；日志加 `[任务点N]` 前缀；全部任务点结束后才汇总完成；任一任务点停止会停止其余任务点。
- **验证**：✅ 单元测试：两个 frame（12 题 / 3 题）均被选中；○ 真实页面待复测。
- **复发风险**：中。如果两个任务点实际在**同一文档**而不是独立 frame，需要进一步调整同文档扫描/分段逻辑。



### D1. 静态内容脚本与动态注入重复执行

- **现象**：学习通同时配置了 `content_scripts` 与动态 `executeScript(files)`。
- **风险**：重复注册消息监听、重复 HUD、重复扫描。
- **现状**：每个脚本 IIFE 首行都有 `window.__wg?.xxx` 守卫，第二次执行直接返回；HUD `ensure()` 幂等。
- **验证**：◐ 代码层保证；未专门写测试。
- **复发风险**：低，但新增脚本必须遵守守卫约定。

### D2. 面板“保存配置”调用 `chrome.permissions.request`

- **现象**：`host_permissions` 已覆盖全部 https，却仍按 Base URL 申请域名。
- **风险**：manifest 未声明 `optional_host_permissions`；在部分浏览器/企业策略下可能直接返回 false，报“未授权访问该 API 域名”。
- **现状**：✅ 用户环境可保存；属于冗余逻辑与技术债。
- **建议**：要么删除动态申请，要么补 `optional_host_permissions` 并收窄全站权限。

### D3. 缺少 CI 与仓库内自动化测试

- **现象**：0.5.3 之前无 Git；当前已有 Git 仓库与 tag，但 mock 仍只存在于 `%TEMP%`，没有 CI。
- **风险**：改动无自动回归基线，问题容易反复。
- **现状**：靠 `node --check` + 手工 mock + 用户真机截图验证。
- **建议**：把 mock 与测试脚本迁入 `tests/`，并在 `.github/workflows` 中加入静态检查。

## 附：快速排查顺序（真机 0 题 / 漏题 / 不写入）

1. 看面板状态是“未获取到页面信息”还是“识别到 0 道题”：
   - 前者 = 注入/内容脚本问题（看 `脚本注入 / 自检` 日志）；
   - 后者 = 解析问题（看探测诊断：容器命中、`typeName`、标签、iframe）。
2. 确认扩展已重新加载、面板已重开、页面已 `Ctrl+F5`。
3. 看“各 frame”：题数/标签数最多的是不是题目真正所在的 frame。
4. 单题不写入：看日志 `第 N 题写入异常：…`（0.5.3 起不会中断整卷）。
5. 题干乱码：判定为字体加密问题，不是解析问题。
