# 题灵 Quizora v0.5.8

本次修复 0.5.7 在空框路径中引入的运行时错误，并为“点击也无法产生输入框”的页面增加最后回退。

## 直接失败的原因

0.5.7 的 `findBlankBoxes()` 调用了 `isVisible()`，但该函数只在 `cx-adapter` 内部存在，`cx-fill` 中未定义。只要进入空框点击路径就会抛：

```
ReferenceError: isVisible is not defined
```

导致本应填写的题直接失败。0.5.8 已移除该依赖，改用 `isConnected` + `getBoundingClientRect()` 判断。

## 修复内容

- 修复 `isVisible is not defined` 运行时错误。
- 点击顺序改为：整行 → 该行内最宽的空内容框；同时派发 `pointerdown / mousedown / mouseup / click`。
- 若点击后仍没有 input/textarea，则把该空框临时设为 `contenteditable` 并直接写入答案。
- 此类回退在日志中标注 **“空框直写，请核对”**，不会静默当成正常保存。
- 启动/探测日志增加“空框样本”HTML 片段，便于按真实 DOM 精确适配。

## 安装

1. 下载 `quizora-v0.5.8.zip` 并完整解压。
2. `edge://extensions` → 开发人员模式 → 加载解压缩的扩展 → 选择 `quizora-v0.5.8`。
3. 重新加载扩展后刷新页面；建议先“清空缓存”，再探测/开始。

## 重要说明

“空框直写”只能保证页面上**看到答案文字**；如果该页面把答案存在自定义状态而不是 DOM 文本，提交时可能不识别。复测时请：

1. 填写后点一下其他题目，确认文字没有被页面清空；
2. 再点“暂时保存/提交”查看是否被系统接收；
3. 若文字消失或提交后为空，请把日志中的 `空框样本：<...>` 整行发回，我将按真实 DOM 改成写入它的隐藏字段/接口。
