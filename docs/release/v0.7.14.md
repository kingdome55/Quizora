# 题灵 Quizora v0.7.14

> 发布日期：2026-11-03 · 类型：修复（wr is not defined / 编辑器优先级）

## 一、现象

日志：

```text
已写入代码（115 字符 · cm5 · cm5:0）
停止：运行异常：wr is not defined
```

代码已经写入，但随后在写后兜底判断处抛出 `ReferenceError`。

同时 `可选编辑器：dom-monaco@#0，cm5@#0`，插件优先选了 `dom-monaco`（DOM 兜底），而不是可读写的 `cm5` API。

## 二、根因

1. `wr` 在写入分支内用 `const wr` 声明；写后 `if (wr.visible === false)` 在分支外引用，作用域错误。
2. 编辑器排序把 `dom-monaco` 与 `monaco` 视为同一优先级，且排在 `cm5` 前面；实际页面是 CodeMirror 5，应该优先用 `cm5` API 覆盖式 `setValue`。

## 三、修复

- `wr` 改为外层 `let wr = null`，写入分支内赋值；写后兜底用 `wr?.visible`。
- 编辑器排序改为：
  1. 可见优先；
  2. MAIN world API 优先于 DOM 兜底；
  3. 类型/面积/长度。
- 页面同时有 `dom-monaco` 与 `cm5` 时优先选 `cm5`，日志应显示 `编辑器：cm5`。
- 写入成功后把 `model.type` 更新为实际写入类型（如 `cm5`），后续重试直接走 API。
- 0.7.13 的 CodeMirror 误判/重复代码修复与模板清理继续保留。
