# 题灵 Quizora v0.7.16

> 发布日期：2026-11-03 · 类型：修复（头歌编辑器能写入但重复代码）

## 一、现象

头歌执行后编辑器出现两份模板：

```sql
use library;
#代码开始
update reader set dhhm='13315667745', sf='工作人员' where xm='陈洁';
#代码结束
select * from reader; use library;
#代码开始

#代码结束
select * from reader;
```

第一份是写入的答案，第二份是页面原始模板，两者被拼接而不是覆盖。

## 二、根因

1. **DOM 兜底追加**：写入目标被判定为隐藏模型（`visible=false`）时，`edu-main` 会再执行一次 DOM 覆盖。DOM 路径使用 `execCommand('insertText')`，在 CodeMirror 5 中它不会替换模型内容，只在光标处追加，因而把答案插到模板前面。
2. **模板合并不清理**：`mergeWithTemplate` 在答案自带 `#代码开始/#代码结束` 时直接原样返回；如果答案或历史编辑器已经包含多组标记，重复模板会原样保留。

## 三、修复

1. `mergeWithTemplate` 新增 `markerBodies/pickBody`：收集每一组 `#代码开始/#代码结束` 之间的代码，取内容最长的一组；再按当前模板**第一组前缀 + 最后一组后缀**重组，中间重复模板全部丢弃。
2. API 写入后不再执行 DOM `insertText` 兜底。目标为隐藏模型时，背景在全部 frame 中查找可见编辑器，用覆盖式 `setValue` 重写；仍找不到可见编辑器则停止，不点评测。
3. CodeMirror 5 的 `visible` 改为“真实渲染（有布局尺寸）”。编辑器在视口外不再被误判为隐藏；是否在视口内只影响写入优先级。
4. 0.7.15 的 `domFind` 跨类型可见面积选择、`pickEditor` 视口过滤继续保留。

## 五、真机验收

日志应为：

```text
编辑器：cm5 · frame#x · sql · 模板 N 字符
已写入代码（N 字符 · cm5 · cm5:x）
```

写入后编辑器只应保留一份：

```sql
use library;
#代码开始
<答案>
#代码结束
select * from reader;
```

不应再出现：

```text
DOM 覆盖写入失败
已通过 DOM 覆盖写入可见编辑器
写入目标是隐藏编辑器，尝试 DOM 覆盖…
```
