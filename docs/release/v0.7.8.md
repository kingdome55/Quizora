# 题灵 Quizora v0.7.8

> 发布日期：2026-11-03 · 类型：头歌参考答案优先 + 稳定性修复

## 一、根因

0.7.7 反馈“参考答案仍提示禁止查看 / 没有解除限制提示”，排查后确认：

1. **任务数据走 XHR，不走 fetch**：头歌页面使用 axios（XMLHttpRequest）加载 `/api/tasks/...json`；0.7.7 只 hook 了 `window.fetch`，任务字段从未被改写，所以点击「参考答案」仍触发“禁止查看答案”。
2. **停止只通知了顶层 frame**：`stopRun` 原先只向 frame 0 发 `WG_STOP`；实际运行的 `edu-main` 在任务 frame 中仍保持 `running=true`，再次开始被忽略，探测也容易读到旧状态。
3. **探头过度依赖评测按钮**：快照要求 `findExact('评测')` 成功；评测冷却/按钮暂时不可用时，探测直接识别为 0 题。
4. **评测冷却未充分等待**：原逻辑只等 30 秒，且只对失败重试生效；连续评测时按钮仍可能锁定。

## 二、参考与方案

参考实现：

- `lcandy2/user.js` —《头歌复制助手》：`document_start` hook `fetch` 改写任务权限字段。
- `lcandy2/user.js` —《头歌助手》：参考答案面板调用官方 `get_answer_info.json` / `unlock_answer.json`，并提示金币/查看记录。
- `alumkal/educoder-helper`：公开签名实现 `md5(base64("method=GET&ak=...&sk=...&time=..."))`，用于对齐头歌 API 的 `X-EDU-Signature` / `X-EDU-Timestamp`。

0.7.8 方案：

1. **同时 hook fetch 与 XHR**：改写任务 JSON；采集任务 ID、`Pc-Authorization`、`X-EDU-*` 请求头；提供 `REFERENCE_REQUEST` / `REFERENCE_UNLOCK_REQUEST` 消息桥。
2. **参考答案优先**：`edu-main` 启动后先读取官方参考答案；拿到后直接写入编辑器并评测；参考答案未通过自动回退 AI。
3. **未解锁处理**：默认只记录“参考答案未解锁（需 N 金币）”并回退 AI；侧边栏新增“自动解锁（消耗金币/留记录）”开关，默认关闭。
4. **冷却等待**：`cooldownText()` + `isDisabled()` 检测冷却，评测前/失败后最多等待 90 秒。
5. **停止与探测修复**：`stopRun` 向所有已启动 frame 广播 `WG_STOP` 并清理 frame 缓存；探测在任务页只要看到编辑器或评测按钮即识别 1 题；重复开始先停止旧任务再重启。

## 三、验证

- Node VM：XHR 任务 JSON 11 项断言全部通过；状态 3 参考答案解析、状态 1 未解锁识别通过；MD5 签名与 Node crypto 一致；`edu-main` 参考答案优先写入/评测流程通过。
- 真实接口匿名验证：带签名请求 `get_answer_info.json` 返回 `{"status":401,"message":"请登录后再操作"}`（不再是 `status:-102` 时间不匹配，说明签名被接受）；响应头 `Access-Control-Allow-Origin: https://www.educoder.net` 且 `Access-Control-Allow-Credentials: true`，CORS 可用。
- 构建：37 文件，292.2 KB，SHA256 `FE3BF1807678A5E43D2F26961CDC9554A106D5C6893E45D11FB0BACA68587862`。
- 真机待验证：打开头歌任务页 → 点开始 → 日志应出现 `已读取平台参考答案（N 字符）` 与 `使用平台参考答案写入（N 字符）`；若出现 `参考答案未解锁`，勾选自动解锁或先手动解锁。

## 四、边界

- 参考答案正文仍由平台官方接口返回；不伪造答案、不修改金币/成绩/评测状态。
- 考试页（`/exam`）继续硬性跳过。
- 自动解锁会消耗金币并留下查看记录，默认关闭。
