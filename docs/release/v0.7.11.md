# 题灵 Quizora v0.7.11

> 发布日期：2026-11-03 · 类型：修复（头歌仍写入隐藏 Monaco model）

## 一、现象

0.7.10 日志仍然显示 `已写入代码（107 字符）`，但页面编辑器保持模板：

```sql
use library;
#代码开始

#代码结束
```

随后直接点评测，结果不匹配。

## 二、根因

0.7.10 的可见优先依赖 `monaco.editor.getEditors()`。部分头歌页面该 API 不可用或返回空，导致所有 model 的 `visible` 都是 false，排序仍按内容长度选中隐藏 model。

## 三、修复

1. **DOM view-text 回退**：若 `getEditors()` 为空，读取可见 `.monaco-editor .view-lines` 文本，与每个 model 的 value 做前缀匹配，匹配到的 model 标记为可见并记录面积。
2. **写后可见回读**：`EDU_SET_CODE` 成功后用 `domFind()` 读取当前可见编辑器；若内容不包含目标代码，自动用 `domSet()` 覆盖可见编辑器。
3. **失败即停止**：DOM 覆盖后仍不一致则记录错误并停止，不再“写隐藏后直接点评测”。
4. 日志增加编辑器类型/id：`已写入代码（N 字符 · monaco · monaco:2）`，便于定位。

0.7.10 的模板合并与无记录读取继续保留。

## 四、验证

- 0.7.9 可见/隐藏 model 测试、0.7.10 模板合并测试继续通过。
- 新增 DOM view-text 回退与写后回读逻辑（真机待日志确认）。
- 构建：37 文件，295.6 KB，SHA256 `F612EF7E1CC8D009B65078B7C294E1489D280173EA00CE23D6E75C4B737DBF36`。

## 五、真机验收

1. 日志应出现 `已写入代码（N 字符 · monaco · monaco:N）`；
2. 紧接着应出现 `已写入代码` 后页面编辑器立即变化；
3. 若出现 `写入后可见编辑器未包含目标代码...尝试 DOM 覆盖`，随后应出现 `已通过 DOM 覆盖写入可见编辑器`；
4. 若出现 `DOM 覆盖后可见编辑器仍未包含目标代码，停止评测`，把该日志与 `编辑器：...` 发回。
