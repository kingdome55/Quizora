# 题灵 Quizora v0.7.5

> 发布日期：2026-11-02 · 类型：修复（头歌重复写入 + 读题可见性）

## 问题

头歌自动答题一次运行后，编辑器里出现两份相同代码（缩进可能不同），且用户不确定插件是否读到了任务说明。

## 根因

`EDU_DOM_SET` 在 `insertText` 成功后，又执行了 textarea setter / 合成 paste 兜底；两条路径都写入，导致同一份代码出现两份。缩进不同是因为 `insertText` 走编辑器自动缩进，而 setter 写入原始文本。

## 0.7.5 修复

- DOM 写入改为“确认没写进去才兜底”：
  - 先 `selectAll + insertText`；
  - 等待 220ms，读回编辑器内容；
  - 只有内容确实未变化，才尝试合成 paste；
  - 仍没变化且活动元素是 textarea 时，才用原生 setter。
- 写入前比较编辑器内容：与生成代码完全相同则跳过重复写入；检测到多份相同代码时日志警告并重写清理。
- 运行中再次收到 `WG_START`（双击开始/重复启动）直接忽略，避免两条流程同时写。
- 启动日志新增 `说明 N 字符` 与 `任务说明预览：…`，可确认插件确实读到了题目。
- 代码生成提示词强调：保留所有 `#题目N`、`use library`、`#代码结束`；逐题核对表名/字段/distinct/排序/子查询后再输出。

## 验证

- 头歌两关自动答题 mock 通过；日志显示 `说明 208 字符` 与说明预览。
- 同源 iframe CodeMirror 6 的 DOM 写入 mock：`beforeLength=11` → `length=40`，一次写入，无重复。

## 使用

1. 加载 v0.7.5，刷新头歌任务页。
2. 点“开始”；日志会显示任务说明字符数与预览。
3. 若编辑器仍有重复内容，日志会出现“编辑器已有 N 份相同代码，重写清理”。
4. 自动答题卡住时，仍可直接粘贴自己的代码手动评测。

## 说明

- 自动答题仍是实验能力；粘贴解锁是兜底。
- 真实头歌页面的编辑器识别/评测文案可能因平台改版失效。
