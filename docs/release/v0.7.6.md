# 题灵 Quizora v0.7.6

> 发布日期：2026-11-02 · 类型：准确率优化（不改速度与功能）

## 一、Java 软件为什么更快、更准

分析上传的 `拖亿下-Java源码-v1.0.3`（Android WebView + `solver.js` + Java `AiClient`）：

| 维度 | Java 软件 | 我们的插件 |
| --- | --- | --- |
| 请求方式 | `WorkActivity.buildPrompt()` 把整卷可作答题**一次**打包，单次 `chat/completions` 返回 JSON 数组 | 逐题调用 `SOLVE_EXAM`，N 题 N 次网络请求 |
| 模型 | 默认 `deepseek-chat`（`Prefs.aiModel`），温度 0.2 | 用户选择 DeepSeek Flash（速度优先、推理较弱） |
| 答案格式 | 单选/多选写**选项字母**（A/B/C/D，多选连写 ACD），判断写“对/错”，填空用 `#` 分隔 | 要求 0 基 `indices`，容易下标错位 |
| 题干 | `solver.js` 输出结构化 `stem/options/typeName`，题号与类型分离 | DOM 文本可能混入题号、题型、选项自带标签 |
| 缓存 | `Prefs` 本地 `ansCache`，key=`typeName|stem`，重复题直接命中 | 有缓存，但只缓存部分类型且校验严格 |
| 写入 | 一次 `CRSolver.fill(payload)`，返回逐题 `ok/why` | 逐题写入，客观题未校验是否真的选中 |

结论：
- **速度优势**主要来自“一次请求 + 本地缓存”，不是单题算法更快；
- **准确率优势**主要来自“更强的默认模型 + 字母答案 + 干净题干 + 整卷上下文”，以及重复题缓存。

## 二、0.7.6 只执行的准确率行动

- 选择题答案改为**选项字母**（A/B/C/D，多选连写），兼容选项全文、判断“对/错”与旧 `indices`。
- 题干/选项发送前清洗：去题号、题型前缀、选项自带的 `A./B.` 标签与多余空白。
- `runJson` 对无效输出（格式错误、下标越界、单选返回多个、填空数量不符）**重试 3 次**，不再第一次无效就失败。
- 填空题答案数量必须严格等于空格数；不足/多出都重试，避免直接填入错误的部分答案。
- 客观题填入后校验：目标选项必须全部选中；单选/判断不能多选；未选中标记失败。

## 三、没有执行（属于速度/架构，保持现状）

- 一次批量请求整卷（会改变请求结构/速度）
- 并行请求、题库 API、OCR、自动提交
- 默认模型从 Flash 换成 `deepseek-chat`（这是速度/设置变更）

## 四、模型建议

如果更看重准确率，可在“设置 → 模型”里把模型切到 `deepseek-chat` 或更强的推理模型；插件没有替你改默认模型，保持你当前的速度设置。
