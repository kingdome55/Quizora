# 题灵 Quizora v0.7.2

> 发布日期：2026-11-02 · 类型：修复（头歌编辑器在 sandbox/跨域 iframe 中无法注入）

## 问题

0.7.1 用 `chrome.scripting.executeScript({ world: 'MAIN', allFrames })` 扫描所有 frame，但真实头歌页面把代码编辑器放在 **sandbox / 跨域 iframe** 里，`executeScript` 注入失败，日志显示“未找到 Monaco/Ace/CodeMirror 编辑器”。

## 0.7.2 修复

- manifest 增加 `match_origin_as_fallback: true`：内容脚本可进入 `about:blank` / `srcdoc` / sandbox（opaque origin）iframe。
- 新增 DOM 回退链路：
  - background `EDU_FIND_EDITOR` 先用 MAIN world 扫描；没有结果时，通过 `chrome.tabs.sendMessage` 逐帧调用 `EDU_DOM_FIND`。
  - 内容脚本扫描当前 frame、同源 iframe 的 document、open shadow DOM，识别 `.monaco-editor` / `.cm-editor` / `.ace_editor` / `.CodeMirror` / textarea / contenteditable。
  - `EDU_DOM_SET` 在编辑器 frame 内执行：点击/聚焦 → Ctrl+A/selectAll → `execCommand('insertText')`；失败则合成 `ClipboardEvent('paste')` + `DataTransfer`（CodeMirror 6 / Monaco 按 input/paste 处理）；textarea 再回退原生 setter。
- 日志显示 `编辑器：dom-monaco/dom-cm6/... · frame#N`；写入失败记录 active element（标签+class），便于定位。
- 原有 MAIN world Monaco/Ace/CM 写入优先保留；DOM 只作为不可注入时的回退。

## 验证

- 本地 mock：编辑器在**同源 iframe** 内，top frame 的 `EDU_DOM_FIND` 跨 iframe 找到 `dom-cm6`，`EDU_DOM_SET` 成功把 `#代码开始/#代码结束` 替换为 `CREATE DATABASE library; show databases;`，返回 `inserted=true`。
- 两关流程 mock 仍通过。

## 使用

1. 加载 v0.7.2，刷新头歌任务页。
2. 关闭“演练模式”，点“开始”。
3. 看日志第一行：
   - `编辑器：monaco/ace/cm5/cm6 ...` → MAIN world API；
   - `编辑器：dom-monaco/dom-cm6/... frame#N` → DOM 回退；
   - 仍报“未找到代码编辑器” → 把日志与探测快照 `buttons/result/hasEditor/hasEvaluate` 发回。
4. 通过后自动下一关；刷新自动续跑。

## 限制

- 只填充主编辑器；多文件任务暂不支持。
- 若编辑器所在 frame 连内容脚本都无法注入（极少见），仍需后续考虑 CDP 输入方案。
- 头歌考试页不自动作答。
