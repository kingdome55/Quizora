# 题灵 Quizora v0.6.0

> 发布日期：2026-11-01 · 类型：修复 + 能力补齐

## 为什么发这个版本

0.5.9 在真实学习通页面上仍然报“部分空未填”，同时题干/选项出现“媏/媐/媎”一类替换字，导致模型判题准确率下降。本版本不再猜测 DOM，而是按成熟开源项目的实现落地两条链路。

## 1. 填空题：按真实答案格写入

调研结论（cxmooc-tools / OCSJS）：

- 左侧 `span.font14.tiankong` 只是“第 N 空”**标签**，不是答案框；
- 真正答案格是 `.XztiHover1`：
  - 作业页在 `.Zy_ulTk` 内，格内通常是 `input.inp`；
  - 考试页在 `.Cy_ulTk` 内，格内通常是 UEditor（`textarea[name]` + 编辑 iframe）。

0.6.0 的写入顺序：

1. 按“第 N 空”标签排序答案格；
2. 格内有 `input.inp` → 原生 setter 写入并派发 input/change；
3. 格内是 UEditor → 先写同源编辑 iframe，再通过 background 在 MAIN world 调 `UE.getEditor(name).setContent()+sync()`；
4. 都失败时才 hover/click 激活答案格并重试；
5. 只有实际写入的空数达到答案数才标记完成。

同时把 `.XztiHover1` / `.Zy_ulTk` / `.Cy_ulTk` 从选择题选项收集中排除，避免填空题被误判成选择题。

## 2. 字体反爬：扫描前解密

学习通用 `font-cxsecret` 把真实字形映射到随机汉字码位。0.6.0：

- 读取 `<style>` 内嵌的 base64 TTF；
- 用 Typr.js 解析字形，对 CJK 码位计算 `glyphToPath` 的 MD5；
- 查内置映射表（与 OCSJS 使用的 `table.json` 相同，MIT）；
- 在 `cx-adapter.norm()` 中解密题干、选项、题型标签，并改写页面 `.font-cxsecret` 文本节点；
- 探测与开始都会等待字库就绪；日志出现“字体解密已就绪：N 个字形”。

映射表未命中时保留原文，不阻塞答题。

## 3. 验证

本地 headless Edge mock（7 组，全部通过）：

| 场景 | 结果 |
| --- | --- |
| 0.5.x 旧结构：span 标签 + 同级可编辑框 | `甲/乙/丙`，`complete=true` |
| `.XztiHover1 + input.inp` ×3 | `甲/乙/丙`，`complete=true` |
| `.XztiHover1 + UEditor iframe` ×3 | `缆芯/加强件/护层`，`complete=true` |
| input + UEditor 混合 ×2 | `甲/乙`，`complete=true` |
| 两道填空 + 重新扫描 | 作用域隔离正确，`answered=true` |
| 标签后紧跟答案格（class 改版，无 `.XztiHover1`） | `甲/乙`，`complete=true` |
| 3 个格子只返回 2 个答案 | `complete=false`，标记“部分空未填” |

## 4. 安装

1. 下载 `quizora-v0.6.0.zip` 并完整解压；
2. `edge://extensions` → 开发人员模式 → 加载解压缩的扩展 → 选择解压目录；
3. 打开答题页 → `Ctrl+F5` → 重开侧边栏。

## 5. 已知限制

- 字体映射表是第三方静态数据；若学习通更换字体生成方式，可能 `mapped=0`，此时自动回退原文；
- 简答题跨 frame 写入仍待真机复测；
- 扩展只填写，不自动提交。
