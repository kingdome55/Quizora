# 题灵 Quizora v0.7.9

> 发布日期：2026-11-03 · 类型：修复（头歌写入隐藏 Monaco model）

## 一、现象

0.7.7 之后，头歌日志显示 `已写入代码（111 字符）`，但页面可见编辑器仍是空模板：

```text
use library;
#代码开始

#代码结束
```

随后插件直接点击“评测”，结果自然是 0/1 测试集不匹配。

## 二、根因

0.7.7 打开「参考答案」入口后，头歌页面会额外创建一个**隐藏的 Monaco model**（答案预览/缓存）。`eduEditorScript` 原逻辑按**内容长度降序**选择 model：

```text
隐藏答案 model 更长 → 被选中
可见模板 model 较短 → 被忽略
```

于是代码写进了隐藏 model，页面上的编辑器没有变化，评测读取的是空模板。

## 三、修复

- `eduEditorScript` 通过 `monaco.editor.getEditors()` 获取编辑器实例，结合 `getDomElement()` 的面积标记 `visible / area`；排序改为：
  1. 编辑器类型；
  2. **可见优先**；
  3. DOM 面积大优先；
  4. 内容长度。
- `EDU_SET_CODE` 收到隐藏 `editorId` 时，**重定向到当前可见 model**，不再写隐藏 model。
- `edu-main` 日志会显示 `隐藏模型` 警告；正常日志应是不带“隐藏模型”的 `编辑器：monaco · ... · 模板 N 字符`。
- 0.7.8 的参考答案优先、XHR hook、90 秒冷却等待、停止/探测修复全部保留。

## 四、验证

- Node VM：同时构造可见 model（25 字符）与隐藏 model（120 字符）：
  - `find` 选中可见 model；
  - `set` 传入隐藏 `editorId`，仍写入可见 model；
  - `set` 传入可见 `editorId`，写入可见 model。
- 构建：37 文件，293.0 KB，SHA256 `DDD132E13904D8264A8BC748723680A29A4DF14F9CC043D3693F30EE1B294B7A`。
- 真机验收：启动日志出现 `已写入代码` 后，页面编辑器应立刻显示答案；评测不再读取空模板。

## 五、边界

- 参考答案正文仍走平台官方接口；不伪造答案、不改金币/成绩。
- 若页面在写入后主动重置编辑器（例如切换代码文件），会按当前可见 editor 重新选择；日志可定位。
