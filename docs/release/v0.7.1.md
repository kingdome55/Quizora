# 题灵 Quizora v0.7.1

> 发布日期：2026-11-02 · 类型：修复（头歌编辑器识别）

## 问题

真实头歌任务页中，左侧任务说明、右侧编辑器、评测按钮不一定在同一个 frame；编辑器还可能不是 Monaco。0.7.0 只在内容脚本所在 frame 读取 `window.monaco`，所以会一直停在“等待 Monaco 编辑器”，约 25 秒后报“未检测到 Monaco 编辑器”。

## 0.7.1 修复

- 新增 `EDU_FIND_EDITOR`：background 用 `chrome.webNavigation.getAllFrames` 枚举所有 frame，逐帧在 MAIN world 扫描编辑器。
- 支持 6 类编辑器：
  - Monaco：`monaco.editor.getModels()` + `setValue`
  - Ace：`.ace_editor` → `env.editor.setValue`
  - CodeMirror 5：`.CodeMirror` → `CodeMirror.setValue`
  - CodeMirror 6：`.cm-editor` → `cmView.view.dispatch`；无实例时 `.cm-content` + `execCommand('insertText')`
  - textarea：原生 setter + input/change
  - contenteditable：焦点 + `insertText`
- 写入目标带 `frameId + editorId`，编辑器在子 iframe 也能写。
- 启动日志输出：`编辑器：monaco/ace/cm5/cm6 · frame#N · 语言 · 模板 N 字符`。
- 下一关重新跨 frame 发现编辑器，兼容页面重建。
- 结果面板解析、评测冷却、失败重试、考试页拒绝逻辑保持不变。

## 验证

- headless Edge mock：两关通过（含一次失败重试），日志出现编辑器类型与 frame。
- 语法检查与构建通过。

## 使用

1. 重新加载 v0.7.1，打开头歌任务页。
2. 关闭“演练模式”，点“开始”。
3. 看日志第一行 `编辑器：…`：
   - 出现 `monaco/ace/cm5/cm6` 说明已找到真实编辑器；
   - 若仍报“未找到编辑器”，把日志与探测快照的 `buttons/result/hasEditor/hasEvaluate` 发回。
4. 通过后自动进入下一关；整页刷新自动续跑。

## 限制

- 只填充主编辑器；多文件任务暂不支持。
- 头歌考试页不自动作答。
- 代码生成质量依赖任务说明完整性。
