# 开发历程

> 重要前提：**0.5.3 之前项目没有 Git 仓库**，早期 commit、分支或 tag 无法回溯。本章程由三份原始方案文档（`docs/archive/`）、多轮开发对话记录和当前代码交叉还原。版本号只能从 `manifest.json` 的修改与对话记录中确认一部分，0.1.0 → 0.4.9 之间的具体递增无法精确还原，已在相应位置注明。

## 1. 需求起源

| 阶段 | 需求 | 结论 |
| --- | --- | --- |
| 起点 | 在已经打开的 Edge Wayground 对局页自动完成 150 道题，人工操作太慢 | 需要“不刷新页面即可注入”的方案 |
| 形态选型 | 插件 / 油猴 / 控制台 / Playwright | 选 **Edge MV3 扩展**：只有扩展能向已打开标签注入且不丢对局进度 |
| 扩展到学习通 | 学习通整卷考试/作业，含单选、多选、判断、填空、简答、图片题；整卷扫描、自动填写、不提交 | 新增学习通适配层 |
| 再扩展 | 任何网页只要有题目、能选、能填就能用 | 新增通用站点兜底 |
| 质量诉求 | 跳过已作答但低置信度也必须填；删除二次复核；恢复 Flash 速度 | 形成 0.4.x 的最终行为 |

来源：`docs/archive/wayground-auto-answer-extension.md`、`docs/archive/wayground-auto-extension-delivery-plan.md`、`docs/archive/chaoxing-exam-extension-plan.md`。

## 2. 阶段一：Wayground 单题自动答题（0.1.0）

**目标**：接管已打开的对局页，逐题识别、判题、点击，页面自动推进。

**落地内容**（历史文档记载）：

- MV3 扩展骨架、侧边栏控制台、Service Worker。
- `adapter.js`：题号计数器、题干、选项三级兜底（`aria` → `group` → `geo`）、输入框、诊断快照。
- `solver.js`：缓存 → 字母重排规则 → LLM。
- `main.js`：单题状态机、点击序列、推进校验（8s 重试 / 18s 暂停）、题号回退跟随。
- `llm.js`：OpenAI 兼容、JSON 宽松解析、400 时降级关闭 `response_format`、重试。
- `cache.js`：题干 + 排序后选项的 FNV hash 缓存。
- `hud.js`：Shadow DOM 悬浮状态条，支持 HUD 内停止。
- 安全阀：演练模式、低置信度暂停、`Alt+Shift+S`、面板/HUD 停止。

**验证**：语法、manifest、字母重排算法通过；真实页面选择器与端到端在交付时尚未验证（见历史文档“未验证”段落）。后续用户真机使用反馈为可用。

## 3. 阶段二：学习通整卷（0.4.x）

**方案要点**（`chaoxing-exam-extension-plan.md`）：

- 整页多题扫描，而不是一题一推进；
- 题型覆盖单选、多选、判断、填空（多空）、简答/论述；
- 只填不交；
- 新增 `sites.js` 站点注册与 `cx-adapter/cx-fill/cx-main`；
- 复用 HUD、配置、缓存、面板。

**开发中实际发生的主要迭代**（按问题出现的先后，非版本号顺序）：

1. 只匹配 `/exam|/work` 导致章节页（`studentstudy`）不注入 → 学习通改为全站匹配。
2. 题目在 iframe 内 → 从“猜一个 frame”改为“全 frame 注入 + 逐帧探测择优”。
3. `frameId` 失效报 `No frame with id ...` → 停止改为广播、页面切换复位、启动前先停旧运行。
4. 探测卡顿、点按钮无响应 → 逐帧探测 + 结果缓存，避免每次全帧重扫。
5. 选项点击成功但插件判“失败” → 无 `input` 的选项块不再硬校验选中 class。
6. 填空题只有 input 才识别、富文本编辑区不填 → 支持 `textarea` / `contenteditable` / UEditor，并在考试模式点每题“保存”。
7. “跳过已作答”曾用全局记录，导致不同章节互相跳过 → `DONE_KEY` 按当前页面 URL 隔离。
8. “所有选项都带同一个 class”被误判已答 → 单选要求恰好 1 个选中，多选要求 >0 且 <全部。
9. 用户要求“低置信度也必须填” → 删除低置信度暂停，低置信度照填并在徽标标注百分比。
10. 二次复核导致 Flash 速度明显变慢 → 删除复核，每题一次模型调用。
11. 混合“选择 + 简答”章节识别 0 题（多轮反复）→ 见阶段四。
12. 学习通字体反爬导致题干乱码（“庝 / 庡 / 庤”）→ 影响判题准确率，**至今未解决**。

## 4. 阶段三：通用网页兜底

- `sites.js` 新增 `generic`：任意 http/https 页面。
- 复用学习通脚本：`cx-adapter` + `cx-generic` + `cx-plain` + `cx-fill` + `cx-main`。
- 支持 radio/checkbox、`textarea`/`contenteditable`、纯文本 `A/B/C/D` 选项。
- mock 验证过“单选 + 多选 + 填空”通用页 3/3（历史记录）。

## 5. 阶段四：识别稳定性与真机收敛（0.4.9 → 0.5.3）

### 5.1 为什么“只有选择题的章节能识别”

0.4.9 时期，扫描器遇到**第一个有命中的容器选择器就返回**。同一页里选择题用 `.TiMu`、简答题用 `.questionLi` 时，只会扫描其中一类；再叠加“简答题无编辑器时被 `hasAnswerable` 过滤”，最终表现为 0 题或漏题。

### 5.2 0.5.0：结构无关扫描

- 合并全部容器选择器，不再提前返回；
- 支持 `[typeName]` / `[data-type]` 题型属性；
- 增加“按题型标签锚定”的兜底扫描（`【单选题】`、`（简答题）`、`[单选题]`）；
- 每题构建独立 `try/catch`，单题异常不拖垮整卷；
- mock 回归：8/8 → 后续扩到 10/10。

### 5.3 0.5.1：控件反推与去重修复

- 新增：即使没有标准容器类、题型标签也被字体加密，也能从 radio/checkbox/`.answerBg`/编辑器反推题目块；
- 修复“同一题被两个来源命中时两份都被去重删掉”的 bug（`contains` 未排除自身）；
- 过滤讨论区/笔记/搜索框，避免把“请输入你的看法”当简答题；
- 自动把探测诊断写入日志（容器命中、typeName、标签、frame、HTML 片段）。

### 5.4 0.5.2：从“解析失败”定位到“内容脚本未响应”

真机截图显示状态为“未获取到页面信息”、日志为“识别到 0 个选项，策略 none”。这说明根本没有快照，问题在注入层：

- 学习通新增**静态内容脚本**（`all_frames: true` + `match_about_blank: true`）；
- 新增 `webNavigation` 权限，用真实 frame 列表逐个探测；
- 0 题时自动补注入并复测；
- 新增 `脚本注入 / 自检 #N v版本 adapter=有/无 main=有/无` 日志；
- 修复 Wayground 回归：Wayground 快照没有 `count` 字段，旧择优逻辑会把它当 0 题。

**真机结果**：混合卷成功识别 11 题（single×5、multiple×5、short×1），自动填写 10 题，第 11 题简答报 `停止：运行异常：Illegal invocation`，整卷中止。

### 5.5 0.5.3：跨 realm 写入修复

- 根因推断：题目 DOM 属于子 frame，但扫描/填写发生在父 frame；`setNativeValue` 用 `instanceof HTMLTextAreaElement` 判断类型，跨 realm 时判断失败，改用 `HTMLInputElement.prototype` 的 setter 调用在 textarea 上 → `Illegal invocation`。
- 修复：
  - `cx-adapter` 只上报**当前文档**的题目（`ownerDocument === document`）；
  - `frame.js` 在题数相同时优先选**更深**的 frame，让操作发生在题目所属 realm；
  - `cx-fill.setNativeValue` 按 `tagName` + `ownerDocument.defaultView` 取原生 setter；
  - `cx-main` 单题异常只标记该题失败，不再中止整卷。
- 验证：语法通过；mock 扫描 `count=10`（single×4 / short×5 / multiple×1）复跑通过。
- **未验证**：真实学习通最后一题简答的写入，需要用户复测。

## 7. 已完成 / 未完成 / 已废弃

### 已完成

- Wayground 单题识别、判题、点击、填空提交、缓存、规则、HUD、面板。
- 学习通整卷扫描（单/多/判断/填空/简答）、按题保存、跳过已答、图片输入、诊断。
- 通用网页兜底（radio/checkbox/纯文本选项/textarea/contenteditable）。
- 面板配置、模型切换、连接测试、图形测试、探测、清缓存、日志。
- 注入层稳定性：静态内容脚本、frame 枚举、深度优先、自检日志。

### 未完成

- 0.5.3 简答修复的真机复测与确认。
- 字体反爬乱码的解码/OCR 方案。
- 多 frame 分摊题目的整卷编排（当前只向一个 frame 发 `WG_START`）。
- 仓库内自动化测试、Git、CI。
- 连线的题型：连线、拖拽、编程、听力（明确不支持）。

### 已废弃 / 已移除

| 功能 | 原因 | 状态 |
| --- | --- | --- |
| 低置信度暂停 | 用户要求低置信度也必须填 | 面板开关与配置项已删除；`main.js` 仍残留分支（死代码） |
| 二答复核 / 高准确率复核 | 显著拖慢 Flash 速度 | 代码已删除 |
| 全局“已处理”记录 | 不同章节/考试互相跳过 | 改为按页面 URL 隔离 |
| 全帧广播停止 | 产生失效 frameId 报错 | 改为运行态复位 + 广播 `WG_STOP`（无 frameId） |
| 全帧长时间扫描 | 探测卡顿 | 改为逐帧探测 + 结果缓存 |

## 8. 历史结论

这个项目不是一次设计完成的，而是被真实页面反复“教育”出来的：

1. 先解决“能不能注入”（扩展形态 + 全帧）；
2. 再解决“能不能识别”（结构无关扫描 + 标签/属性/控件三路锚定）；
3. 最后解决“能不能写对”（realm / frame 归属、编辑器同步、单题容错）。

下一阶段的最大风险不在功能，而在**验证**：0.5.3 的简答修复、Wayground 的 frame 回归都还没有真机结论。
