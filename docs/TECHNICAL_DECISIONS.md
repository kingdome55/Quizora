# 重要技术决策

> 记录“当时为什么这么选、放弃了什么、代价是什么”。证据等级见 README。

## D1. 采用 MV3 扩展，而不是油猴 / 控制台 / Playwright

- **背景**：目标是在**已经进行中的对局**里接管答题，不能刷新页面。
- **备选**：
  - 油猴脚本：通常需要刷新才注入，当前对局会断；
  - 控制台脚本：刷新即失效，Key 暴露在页面上下文；
  - Playwright/CDP：要另起带调试端口的浏览器实例，登录态与对局都要重来。
- **决策**：Edge/Chrome MV3 扩展，`chrome.scripting.executeScript` 注入现有标签页。
- **代价**：需要用户手动加载解压扩展；扩展更新后已打开页面的旧内容脚本会失效，必须刷新页面。
- **证据**：✅ 历史方案文档明确记载该选型理由；✅ 后续真机验证可行。

## D2. 学习通采用“整卷扫描 + 逐题串行”，而不是“一题一推进”

- **背景**：学习通作业/考试页一次性渲染全部题目；Wayground 是页面自动推进的单题模型。
- **决策**：为学习通单独写 `cx-adapter/cx-fill/cx-main`，扫描整页题目，按顺序逐题判题/写入；Wayground 保留原状态机。
- **代价**：需要处理题目容器差异、懒加载、每题保存、跳过已答等整卷特有问题。
- **证据**：✅ `docs/archive/chaoxing-exam-extension-plan.md`；✅ 真机 11 题整卷识别。

## D3. API Key 只保存在 background

- **决策**：Key 存 `chrome.storage.local`，只在 Service Worker 内读取并调用 API；内容脚本只收发题目与答案。
- **收益**：页面上下文（可能被第三方脚本读取）拿不到 Key；也避免 CORS 问题（background 有 host 权限）。
- **代价**：所有判题都要经消息中转；background 是单点，异常会影响全局。
- **证据**：✅ 代码结构；✅ 面板测试连接可用。

## D4. 站点适配采用“注册表 + 独立脚本清单”

- **决策**：`sites.js` 中每个站点声明 `match`、`files`、`label`；background 统一 `siteForUrl` + `pickFrame`。
- **收益**：Wayground 与学习通互不干扰；新增站点只需注册与一组适配脚本；通用站点复用学习通脚本。
- **代价**：各站点脚本不能共享状态；通用站点必须兼容 `cx-adapter` 的启发式。
- **证据**：✅ `sites.js`；✅ 三站点均可用（Wayground 历史真机、学习通真机、通用 mock）。

## D5. Frame 策略：静态注入 + 真实 frame 枚举 + 深度优先 + 单 frame 执行

- **背景**：题目可能嵌套多层 iframe；早期“猜 frame / 全帧广播”导致漏题与 `frameId` 失效。
- **决策**：
  1. 学习通使用静态 `content_scripts`（全 frame + `match_about_blank`），避免点击时注入失败；
  2. `webNavigation.getAllFrames` 枚举 frame 并计算深度；
  3. 题数优先、深度次优，只向选中的 frame 发 `WG_START`；
  4. 每帧只上报**自己文档**的题目（`ownerDocument === document`）。
- **收益**：检测稳定；写入发生在题目真正所属的 realm，避免跨 realm 原生调用异常。
- **代价**：如果同一份卷子的题分散在多个兄弟 frame，只会处理其中一个（见 KNOWN_ISSUES）。
- **证据**：✅ 0.5.2 解决“无快照”；✅ 0.5.3 mock 回归；✗ 简答真机待复测。

## D6. 扫描采用“结构无关的三路锚定”，而不是固定一套选择器

- **背景**：学习通存在多套 DOM（`.questionLi`、`.TiMu`、`mark_item`…），且不同题型混用不同容器；固定选择器会“只识别一半”。
- **决策**：
  1. 容器选择器全量合并（不再首个命中即返回）；
  2. 题型标签锚定（`【单选题】`、`（简答题）`、`[单选题]`）；
  3. `typeName` / `data-type` 属性映射；
  4. 答题控件反推题目块；
  5. 通用扫描兜底 + 合并去重 + 包装层拆分。
- **收益**：混合卷、无标准类名、标签被字体加密（有 `typeName` 时）都能识别。
- **代价**：启发式规则较多，存在误判/性能开销；需要诊断日志辅助排查。
- **证据**：✅ mock 10/10；✅ 真机 11 题。

## D7. 判题“一次调用”，取消二次复核；低置信度仍然填写

- **背景**：用户明确要求恢复 Flash 速度、低置信度也必须填。
- **决策**：每题一次 LLM 调用；删除“高准确率复核”和“低置信度暂停”；低置信度在徽标中标注百分比。
- **收益**：速度恢复；不会因置信度跳过题目。
- **代价**：牺牲了一层答案校验，准确率完全依赖模型与题干质量（字体乱码时风险更大）。
- **证据**：✅ 用户真机反馈速度恢复；✅ 代码中已无复核调用。

## D8. “跳过已作答”按页面 URL 隔离，而不是全局记录

- **背景**：全局 `doneKeys` 造成不同章节互相跳过（第 8 题莫名跳过）。
- **决策**：`DONE_KEY = wg_exam_done_v1:${origin}${pathname}${search}`；同时保留 `isAnswered()` 的 DOM 判定，只有“开启跳过”才生效。
- **收益**：不同考试/章节互不影响；已答题目不覆盖。
- **代价**：URL 含一次性参数时 key 不稳定（见 KNOWN_ISSUES）。
- **证据**：✅ 用户反馈问题消失。

## D9. 缓存：按题干 + 排序选项做 FNV hash，简答不缓存

- **决策**：选择题/填空题缓存 2000 条、按时间淘汰；简答题不缓存，避免不同题目复用同一段回答。
- **收益**：重复题毫秒级；减少模型调用。
- **代价**：题干乱码会让缓存键不稳定；不同选项顺序也能命中（这是刻意的）。
- **证据**：✅ `solver.js` / `cx-main.js`；✅ 用户真机观察到缓存命中。

## D10. 不自动提交，也不做风控规避

- **决策**：只选择/填写；不点交卷；不实现切屏规避、监考绕过、多账号。
- **收益**：边界清晰，风险可控，符合用户“先看效果、不用于真实考试”的诉求。
- **代价**：用户需要手动检查并提交。
- **证据**：✅ 代码无提交调用；✅ 面板/HUD 均提示手动提交。

## D11. 简答写入采用“多路兜底 + realm 安全”

- **决策**：隐藏 textarea、`contenteditable`、UE 实例 `setContent`、iframe body 四种方式依次尝试；`setNativeValue` 按 `ownerDocument.defaultView` 取原生 setter。
- **收益**：兼容不同版本学习通/编辑器；避免 `Illegal invocation`。
- **代价**：逻辑复杂，写入“看起来成功但内部未同步”的风险仍在。
- **证据**：✅ 0.5.2 客观题 10/10；✗ 0.5.3 简答未真机验证。

## D12. 图片题限制：最多 2 张、长边 1024、JPEG 0.82

- **决策**：控制 token 与请求体积，优先保证成功率。
- **代价**：极小文字/公式可能失真；多图题只取最大的两张。
- **证据**：✅ 面板“测试图形”真机返回 `6V`（置信度 98%/99%）。

## D13. 使用 Side Panel，而不是 popup

- **决策**：侧边栏常驻，关闭页面/切换焦点不影响运行；HUD 提供页面内停止入口。
- **代价**：Side Panel 需要较新版本浏览器；面板与页面焦点切换可能影响某些平台的切屏检测（仅提示，不做规避）。
- **证据**：✅ 面板真机可用。

## D14. `host_permissions` 覆盖全部 http/https（开发期取舍）

- **背景**：通用网页需要任意站点；动态注入依赖 host 权限。
- **决策**：直接申请全站权限，换取“任何网页可用”。
- **代价**：权限过大、商店审核不友好、安全面扩大；面板还会动态申请 API 域名（冗余）。
- **后续**：若上架/长期使用，应收窄为按需授权（`optional_host_permissions` + 用户主动授权），见 NEXT_STEPS。
- **证据**：✅ `manifest.json` 现状。
