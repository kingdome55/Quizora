# 下一阶段工作建议

> 原则：先把“已验证”补齐，再谈新功能。当前最大风险是**未验证的修复**与**准确率**，而不是功能数量。

## P0 — 关闭当前阻塞（必须先做）

### P0-3 真机验证头歌（EduCoder）编程作业

- **动作**：在真实头歌任务页（直接打开或学习通内嵌）关闭“演练模式”，点“开始”；观察 1 关失败重试 + 通过进下一关。
- **验收**：
  - 日志出现“第 N 关：…（sql/…）”“已写入代码”“评测通过”；
  - 失败时日志带平台返回的测试集/错误详情；
  - 通过后能进入下一关；整页刷新后自动续跑；
  - 考试页被拒绝。
- **失败处理**：把 `探测` 的 `buttons`、`result` 与日志中的“评测返回：…”原文发回，按真实文案补选择器。

### P0-1 真机复测 0.6.0/0.7.0 学习通

- **动作**：按 `BUILD_AND_TEST.md` 第 6 节执行；重点看第 11 题。
- **验收**：
  - `11/11` 全部填写；
  - 简答编辑区有内容；
  - 日志无 `Illegal invocation` / `运行异常`；
  - 未发生自动提交。
- **失败处理**：保留 `第 11 题写入异常：…` 与 `第 11 题[short] 失败（…）` 原文，按错误类型定位下一个跨 realm 原生调用。

### P0-2 建立可回滚基线

- **动作**：`git init`，提交当前工作树；给 0.5.3（验证通过后）打 tag `v0.5.3`。
- **验收**：`git status` 干净；能从 tag 还原；`docs/DEVELOPMENT_HISTORY.md` 补上 commit 对应关系。

## P1 — 准确率与回归

### P1-1 字体反爬（乱码）专项

- **动作**：
  1. 收集 3–5 道乱码题样本（题干显示 vs `innerText`）；
  2. 验证“截图 + 视觉模型 OCR”的识别质量与耗时；
  3. 评估字体 cmap 解码的可行性（是否可稳定拿到字体文件与映射）；
  4. 只在乱码比例高的题目启用兜底，避免全量变慢。
- **验收**：样本题干可读率 ≥ 90%，单题额外耗时可接受；缓存键稳定。

### P1-2 Wayground 真机回归

- **动作**：用一局测试对局验证探测、演练、实跑 5 题、停止。
- **验收**：无“未识别到题目”；选项点击后页面推进；停止即时生效。
- **风险**：0.5.3 的 `usable/weight` 改动只在代码层修复，未真机验证。

### P1-3 多 frame 分摊题目

- **动作**：设计“多 frame 运行清单”：
  - 向每个 `count > 0` 的 frame 发送 `WG_START`；
  - 全局题目 key 去重（跨 frame）；
  - HUD 只保留一个，停止广播到全部；
  - 进度合并（总数/已填数）。
- **验收**：构造“每题一个 iframe”的 mock，能全部填写且不重复。
- **注意**：必须保留“同文档过滤”，否则父子 frame 会重复答题。

## P2 — 工程质量

### P2-1 测试入仓

- **动作**：
  - 将 `%TEMP%\wg-cx-test` 的 mock 与启动脚本迁入 `tests/`；
  - 增加 `tests/run-checks.ps1`：`node --check` 全量 + manifest JSON 校验；
  - 增加 mock 断言脚本（可用无头浏览器或 Node DOM 方案）。
- **验收**：一条命令跑完静态检查 + mock；失败时返回非 0。

### P2-2 清理死代码与配置

- 删除 `main.js` 的 `pauseOnLowConfidence` 分支、`solver.js` 的 `confidenceThreshold`；
- 同步清理历史注释与文档描述。
- **验收**：全局搜索无残留；Wayground 行为不变。

### P2-3 诊断导出

- 面板增加“导出诊断”：把探测快照、各 frame 摘要、自检结果、最近日志打包为 JSON（下载或复制）。
- **收益**：排障不再依赖用户手动粘贴；也为回归测试提供样本。

### P2-4 权限与密钥

- 方案 A：保留全站权限，但删除 `chrome.permissions.request` 冗余逻辑；
- 方案 B（推荐长期）：收窄为 `optional_host_permissions`，通用站点首次使用时按域名授权；
- 文档明确 Key 明文存储风险与共用电脑注意事项。

## P3 — 体验与扩展

- UEditor 兼容加固：`editor.sync()`、保存按钮文案匹配（保存/暂存/保存答案）；
- 已答 key 稳定化：URL 稳定参数 + 题号/选项序号；
- 支持更多题型（连线/拖拽/编程）需单独评估，不建议短期投入；
- 性能：给 `labelBlocks/controlBlocks` 增加节点上限与耗时日志；
- 面板：显示当前 frame 深度/URL、失败题号列表、可点击跳到题目。

## 建议的执行顺序

```
P0-1 真机复测 0.5.3
  └─ 通过 → P0-2 Git/tag → P1-2 Wayground 回归 → P2-1 测试入仓
  └─ 不通过 → 修简答写入 → 再复测 → 重复直到 11/11
P1-1 字体乱码专项（可与 P2 并行）
P1-3 多 frame（有真实需求再做）
P2-2/P2-3/P2-4 工程清理
```

1. 0.5.3 真机 11/11，简答有内容，无异常中止；
2. Wayground 真机回归通过；
3. Git 仓库建立，0.5.3 有 tag；
4. mock 与静态检查可一条命令复现；
5. 乱码问题有明确的下一步结论（做/不做、怎么做）。
